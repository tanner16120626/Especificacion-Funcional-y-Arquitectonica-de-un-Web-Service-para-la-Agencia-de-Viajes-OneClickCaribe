## 📖 Historia de Usuario

Dado que soy la administradora de One Click Caribe y la agencia empieza a trabajar con una aerolínea, un operador mayorista o una aseguradora de asistencia médica,
Para que el proveedor quede disponible para cotizar y su valor neto a pagar se calcule sin errores a partir de la comisión pactada,
Que el sistema me permita registrar el proveedor turístico clasificado por tipo de servicio, junto con su condición de comisión.

## 🔁 Flujo Esperado

- La administradora obtiene desde la interfaz los datos del proveedor: nombre, NIT, tipo de proveedor, servicios que ofrece, porcentaje de comisión y correo de contacto (procesos PRO-11 y PRO-12).
- El sistema consume el endpoint /api/v1/proveedores de `proveedores.api` con el método POST.
- La capa API valida el formato del JSON y delega el caso de uso a `RegistrarProveedorService`.
- El dominio `directorio_proveedores.domain` exige clasificar al proveedor por tipo de servicio, porque ese tipo determina en qué etapa del proceso puede participar (RN-15).
- El dominio valida que hospedaje, traslados y tours se registren a nombre del operador mayorista y no del hotel final (RN-14).
- El dominio valida la comisión pactada: los tiquetes aéreos se manejan en valor neto, con 0 %, y los demás servicios con 12 % (RN-11).
- El backend consulta la base de datos `bd_proveedores` filtrando por NIT para descartar que el proveedor ya esté registrado.
- Si el proveedor no existe, se registra en el directorio con estado activo y los campos:
- nombre / Nombre comercial del proveedor
- nit / NIT del proveedor
- tipoProveedor / Tipo de proveedor (aerolinea, mayorista o aseguradora)
- servicios / Servicios que ofrece (tiquete_aereo, hospedaje, traslado, tour o asistencia_medica)
- comisionPorcentaje / Porcentaje de comisión pactado
- correoContacto / Correo de contacto comercial

- [ ] Se expone un endpoint POST que recibe en el cuerpo JSON los campos nombre, nit, tipoProveedor, servicios, comisionPorcentaje y correoContacto.

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La tabla de proveedores no contiene un registro con el NIT 900456789-1.
- **Acción:** Ejecutar el endpoint POST /api/v1/proveedores con el mayorista PriceTravel, servicios hospedaje, traslado y tour, y comisionPorcentaje 12.
- **Resultado esperado:**

  - Código HTTP 201 Created
  - Campo success = true
  - Campo data.proveedorId contiene el identificador asignado al proveedor
  - Campo data.estado = "activo"
  - Campo message contiene el texto: "Proveedor registrado exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de proveedores ya contiene un registro con el NIT 900456789-1.
- **Acción:** Ejecutar el endpoint POST /api/v1/proveedores con el mismo NIT.
- **Resultado esperado:**
  - Código HTTP 409 Conflict
  - No se crea un nuevo registro en la tabla de proveedores
  - Campo success = false
  - Campo data.proveedorId contiene el identificador del proveedor existente
  - Campo message contiene el texto: "El proveedor ya se encuentra registrado"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "proveedorId" (texto)
  - "nombre" (texto)
  - "nit" (texto)
  - "tipoProveedor" (texto)
  - "servicios" (lista de texto)
  - "comisionPorcentaje" (número)
  - "correoContacto" (texto)
  - "estado" (texto)
  - "fechaRegistro" (fecha y hora ISO 8601)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** La administradora registra una aerolínea con comisionPorcentaje 12 (RN-11), o un mayorista con el servicio tiquete_aereo, que no corresponde a su tipo (RN-15).
- **Acción:** Ejecutar el endpoint POST /api/v1/proveedores con cada uno de esos datos inválidos.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se registra el proveedor
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "Los tiquetes aéreos se manejan en valor neto, sin comisión" o "El servicio no corresponde al tipo de proveedor", según el caso

### ❌ Caso 5: 

- **Precondición:** La base de datos no está disponible o ocurre un error en la consulta.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible registrar el proveedor"
