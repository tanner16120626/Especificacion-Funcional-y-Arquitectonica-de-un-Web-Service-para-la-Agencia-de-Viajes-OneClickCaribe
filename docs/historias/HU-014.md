## 📖 Historia de Usuario

Dado que soy asesor comercial de One Click Caribe y ya armé la cotización con un proveedor por cada segmento del viaje,
Para eliminar los errores de cálculo manual y entregar al cliente un precio correcto por cada pasajero,
Que el sistema calcule el precio de venta de cada segmento aplicando la comisión de la agencia sobre la tarifa neta, diferenciando adultos y menores.

## 🔁 Flujo Esperado

- El asesor comercial obtiene desde la interfaz la cotización en construcción que desea calcular (proceso PRO-22).
- El sistema consume el endpoint /api/v1/cotizaciones/{cotizacionId}/precios de `cotizaciones.api` con el método POST.
- La capa API valida el formato del parámetro y delega el caso de uso a `CalcularPrecioVentaService`.
- El backend consulta la base de datos `bd_cotizaciones` filtrando por cotizacionId para confirmar que la cotización existe y está en construcción.
- El dominio `construccion_cotizacion.domain` identifica el tipo de servicio de cada segmento y aplica el 12 % de comisión sobre la tarifa neta, excepto en tiquetes aéreos, donde el precio de venta es igual al valor neto (RN-22).
- El dominio recupera las edades registradas en la solicitud y aplica la tarifa de adulto o de menor a cada pasajero (proceso PRO-23, RN-23).
- El dominio usa para el hospedaje la tarifa correspondiente al tipo de acomodación registrado en la solicitud (RN-25).
- Se registran en la cotización los valores calculados por segmento y por pasajero:
- tarifaNetaAdulto / Tarifa neta del proveedor por adulto
- porcentajeComision / 0 en tiquetes aéreos y 12 en los demás servicios
- precioVentaAdulto / Precio de venta por adulto en el segmento
- precioPorAdulto y precioPorMenor / Precio total del viaje por tipo de pasajero
- comisionTotal y precioVentaTotal / Totales de la cotización


## ✅ Criterios de Aceptación

### 1. 🔍 Estructura y lógica del servicio

- [ ] Se expone un endpoint POST con el parámetro cotizacionId en la ruta.
- [ ] Se valida que la cotización exista y esté en estado en_construccion o calculada; una cotización vencida no se recalcula (RN-28).
- [ ] El precio de venta de hospedaje, traslados, tours y asistencia médica es igual a la tarifa neta más el 12 % de comisión (RN-22).
- [ ] El precio de venta de los tiquetes aéreos es igual a la tarifa neta, sin comisión (RN-22).
- [ ] A cada pasajero se le aplica la tarifa de adulto o de menor según la edad registrada en la solicitud (RN-23), y el hospedaje se calcula según el tipo de acomodación (RN-25).
- [ ] La cotización cambia a estado calculada y conserva la comisión estimada para el cálculo posterior del margen.

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La cotización COT-07421 está en estado en_construccion, con cinco segmentos (un tiquete aéreo y cuatro servicios con comisión) para 2 adultos.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-07421/precios.
- **Resultado esperado:**

  - Código HTTP 200 OK
  - El segmento de tiquete aéreo tiene porcentajeComision = 0 y precioVentaAdulto igual a su tarifa neta (1980000)
  - Los demás segmentos tienen porcentajeComision = 12 y precioVentaAdulto igual a la tarifa neta más el 12 %
  - Campo data.precioVentaTotal = 11038400, campo data.comisionTotal = 758400 y campo data.estado = "calculada"
  - Campo message contiene el texto: "Precio de venta calculado exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de cotizaciones no contiene una cotización con el identificador COT-99999.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-99999/precios.
- **Resultado esperado:**
  - Código HTTP 404 Not Found
  - No se calcula ningún precio
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No existe una cotización con el identificador indicado"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "cotizacionId" (texto)
  - "segmentos" (lista), y en cada segmento: "orden" (número entero), "tipoServicio" (texto), "tarifaNetaAdulto", "porcentajeComision" y "precioVentaAdulto" (número decimal)
  - "resumenPasajeros" (objeto con "adultos" y "menores" de tipo número entero, y "precioPorAdulto" y "precioPorMenor" de tipo número decimal)
  - "comisionTotal" y "precioVentaTotal" (número decimal)
  - "moneda" y "estado" (texto)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** La cotización COT-07415 está en estado vencida porque fue emitida un día anterior y no fue pagada (RN-28).
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-07415/precios.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se modifican los precios de la cotización
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "La cotización está vencida. Debe generarse una nueva con tarifas actualizadas"

### ❌ Caso 5: 

- **Precondición:** La base de datos no está disponible o ocurre un error en la consulta.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible calcular el precio de venta"
