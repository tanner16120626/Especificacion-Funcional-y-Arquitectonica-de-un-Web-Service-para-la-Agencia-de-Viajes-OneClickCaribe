## 📖 Historia de Usuario

Dado que soy asesor comercial de One Click Caribe y la cotización del cliente ya está consolidada,
Para formalizar la propuesta ante el cliente y dejar registrado el momento desde el cual corre su vigencia de un día,
Que el sistema me permita enviar la cotización al cliente por WhatsApp, correo o de forma presencial, registrando la fecha y hora de emisión.

## 🔁 Flujo Esperado

- El asesor comercial obtiene desde la interfaz la cotización consolidada y el canal de envío elegido: whatsapp, correo o presencial (proceso PRO-26).
- El sistema consume el endpoint /api/v1/cotizaciones/{cotizacionId}/envio de `cotizaciones.api` con el método POST.
- La capa API valida el formato del JSON y delega el caso de uso a `EnviarCotizacionService`.
- El backend consulta la base de datos `bd_cotizaciones` filtrando por cotizacionId para confirmar que la cotización existe y está en estado consolidada.
- El sistema consulta a `clientes.api` el teléfono o el correo del cliente titular, según el canal elegido.
- El sistema formatea la propuesta final y la envía por el canal elegido; la decisión de emitirla corresponde únicamente al asesor comercial, sin aprobación previa de un supervisor (RN-29).
- El dominio `vigencia_respuesta_cotizacion.domain` registra la marca de tiempo de emisión y calcula el límite de vigencia como el cierre del día calendario en curso (proceso PRO-27, RN-26).
- Se registra el envío y la cotización queda lista para recibir la respuesta del cliente, con los campos:
- canal / Canal de envío (whatsapp, correo o presencial)
- destinatario / Teléfono o correo al que se envió
- fechaHoraEmision / Momento exacto de la emisión
- vigenteHasta / Cierre del día calendario de la emisión


## ✅ Criterios de Aceptación

### 1. 🔍 Estructura y lógica del servicio

- [ ] Se expone un endpoint POST con el parámetro cotizacionId en la ruta y el canal de envío en el cuerpo JSON.
- [ ] Se valida que la cotización exista y esté en estado consolidada.
- [ ] Se valida que el canal sea whatsapp, correo o presencial, y que el cliente titular tenga registrado el dato de contacto que ese canal requiere: teléfono para whatsapp y correo para correo.
- [ ] El envío no requiere aprobación de un supervisor; lo decide únicamente el asesor comercial (RN-29).
- [ ] Se registra la fecha y hora exacta de emisión, y la vigencia se fija hasta las 23:59:59 del mismo día calendario (RN-26).
- [ ] La cotización cambia a estado enviada.

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La cotización COT-07421 está en estado consolidada y el cliente titular CLI-00188 tiene registrado el teléfono +573001234567.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-07421/envio con canal whatsapp.
- **Resultado esperado:**

  - Código HTTP 200 OK
  - Campo data.fechaHoraEmision contiene la fecha y hora del envío
  - Campo data.vigenteHasta corresponde a las 23:59:59 del mismo día de la emisión
  - Campo data.estado = "enviada"
  - Campo message contiene el texto: "Cotización enviada exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de cotizaciones no contiene una cotización con el identificador COT-99999.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-99999/envio con canal correo.
- **Resultado esperado:**
  - Código HTTP 404 Not Found
  - No se envía ni se registra ninguna emisión
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No existe una cotización con el identificador indicado"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "cotizacionId", "clienteId", "canal", "destinatario" y "estado" (texto)
  - "totalCotizacion" (número decimal)
  - "fechaHoraEmision" y "vigenteHasta" (fecha y hora ISO 8601)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** La cotización COT-07421 todavía está en estado calculada, sin consolidar, o el asesor elige el canal correo y el cliente titular no tiene correo registrado.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/COT-07421/envio con cada uno de esos datos inválidos.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se envía la cotización ni se registra la emisión
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "La cotización debe estar consolidada antes de enviarse" o "El cliente no tiene registrado el dato de contacto para el canal elegido", según el caso

### ❌ Caso 5: 

- **Precondición:** La base de datos no está disponible o ocurre un error en la consulta.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible enviar la cotización"
