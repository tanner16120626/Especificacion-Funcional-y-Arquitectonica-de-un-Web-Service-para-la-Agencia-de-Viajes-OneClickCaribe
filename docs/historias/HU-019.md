## 📖 Historia de Usuario

Dado un proceso automático del sistema de One Click Caribe que se ejecuta al cierre de cada día calendario,
Para evitar que se acepte o se venda una cotización con una tarifa que el proveedor ya no sostiene,
Que el sistema se encargue de expirar automáticamente las cotizaciones emitidas ese día que no recibieron pago.

## 🔁 Flujo Esperado

- El programador de tareas del sistema obtiene la fecha de corte al cierre del día calendario (proceso PRO-29).
- El sistema consume el endpoint /api/v1/cotizaciones/expiracion de `cotizaciones.api` con el método POST y la fecha de corte YYYY-MM-DD.
- La capa API valida el formato de la fecha y delega el caso de uso a `ExpirarCotizacionesService`.
- El backend consulta la base de datos `bd_cotizaciones` filtrando las cotizaciones en estado enviada o aceptada cuya vigencia termina en la fecha de corte (RN-26).
- El sistema consulta a `pagos.api` si cada cotización tiene un pago, total o parcial, registrado ese mismo día (RN-27).
- El dominio `vigencia_respuesta_cotizacion.domain` cambia a estado vencida las cotizaciones sin pago e impide su aceptación o pago posterior (RN-28).
- Se registra el resultado del proceso con los campos:
- fechaCorte / Fecha del cierre procesado
- cotizacionesEvaluadas / Cotizaciones revisadas en el cierre
- cotizacionesVencidas / Identificadores de las cotizaciones que pasaron a vencida
- cotizacionesConPago / Cotizaciones que conservan su estado porque recibieron pago


## ✅ Criterios de Aceptación

### 1. 🔍 Estructura y lógica del servicio

- [ ] Se expone un endpoint POST con el parámetro fechaCorte en el cuerpo JSON, invocado por el programador de tareas al cierre del día.
- [ ] Se evalúan únicamente las cotizaciones en estado enviada o aceptada cuya vigencia termina en la fecha de corte (RN-26).
- [ ] Las cotizaciones con pago total o parcial registrado el mismo día conservan su estado, porque su precio quedó garantizado (RN-27).
- [ ] Las cotizaciones sin pago cambian a estado vencida y ya no pueden aceptarse ni pagarse; debe generarse una nueva con tarifas actualizadas (RN-28).
- [ ] Las cotizaciones rechazadas no se modifican y conservan su motivo en el historial.
- [ ] Ejecutar el proceso dos veces para la misma fecha no vuelve a modificar las cotizaciones ya vencidas.

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La tabla de cotizaciones contiene seis cotizaciones enviadas o aceptadas con vigencia hasta el 2026-10-22; dos de ellas tienen pago registrado ese día.
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/expiracion con fechaCorte 2026-10-22.
- **Resultado esperado:**

  - Código HTTP 200 OK
  - Campo data.totalVencidas = 4 y esas cotizaciones quedan en estado vencida
  - Campo data.totalConPago = 2 y esas cotizaciones conservan su estado
  - Campo success = true
  - Campo message contiene el texto: "Proceso de expiración ejecutado exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de cotizaciones no contiene cotizaciones enviadas o aceptadas con vigencia hasta el 2026-10-25.
- **Acción:** Ejecutar el endpoint con POST /api/v1/cotizaciones/expiracion y fechaCorte 2026-10-25.
- **Resultado esperado:**
  - Código HTTP 200 OK
  - Campo cotizacionesEvaluadas = 0
  - Campo totalVencidas = 0
  - Campo totalConPago = 0
  - Campo message contiene el texto: "No existen cotizaciones por expirar para la fecha indicada"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "fechaCorte" (fecha YYYY-MM-DD)
  - "cotizacionesEvaluadas", "totalVencidas" y "totalConPago" (número entero)
  - "cotizacionesVencidas" y "cotizacionesConPago" (lista de texto)
  - "fechaHoraEjecucion" (fecha y hora ISO 8601)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** El programador de tareas envía el parámetro fechaCorte con formato incorrecto (por ejemplo, "22-10-2026").
- **Acción:** Ejecutar el endpoint POST /api/v1/cotizaciones/expiracion con fechaCorte 22-10-2026.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se modifica el estado de ninguna cotización
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "Formato de fecha no válido. Debe ser YYYY-MM-DD"

### ❌ Caso 5: 

- **Precondición:** La base de datos no está disponible o ocurre un error en la consulta.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible ejecutar el proceso de expiración de cotizaciones"
