## 📖 Historia de Usuario

Dado que soy la administradora de One Click Caribe y la orden de venta ya tiene el pago del cliente verificado en su totalidad,
Para cumplir la obligación legal de facturar electrónicamente cada venta ante la DIAN,
Que el sistema me permita generar la factura electrónica de la venta a nombre del cliente titular, transmitirla a la DIAN y enviarla al cliente.

## 🔁 Flujo Esperado

- La administradora obtiene desde la interfaz la orden de venta que debe facturar (proceso PRO-51).
- El sistema consume el endpoint /api/v1/facturacion/generar de `facturacion.api` con el método POST.
- La capa API valida el formato del JSON y delega el caso de uso a `GenerarFacturaElectronicaService`.
- El sistema consulta a `pagos.api` (GET /pagos/orden/{id}/estado) para confirmar que la orden tiene el pago del cliente verificado (RN-53).
- El sistema consulta a `clientes.api` (GET /clientes/{id}/datos-fiscales) los datos del cliente titular y valida que sean suficientes para facturar a su nombre, aunque el pago lo haya hecho un tercero (proceso PRO-53, RN-57).
- El dominio `facturacion_electronica_manual.domain` genera el documento fiscal y lo transmite a la plataforma de la DIAN mediante la API externa de facturación electrónica (RN-51).
- Con la respuesta de la DIAN, se registra el CUFE en la base de datos `bd_facturacion`, y la factura ya no puede eliminarse; cualquier corrección requiere nota crédito (RN-56).
- Se envía la factura al correo del cliente titular y se registra la constancia de envío (proceso PRO-54), con los campos:
- facturaId / Identificador interno de la factura
- numeroFactura / Número consecutivo de la factura
- cufe / Código único de factura electrónica asignado por la DIAN
- clienteId y documentoCliente / Cliente titular a cuyo nombre se emite
- valorTotal / Valor total facturado
- enviadaA / Correo al que se envió la factura


## ✅ Criterios de Aceptación

### 1. 🔍 Estructura y lógica del servicio

- [ ] Se expone un endpoint POST que recibe en el cuerpo JSON el ventaId de la orden a facturar.
- [ ] Se valida que la orden exista y tenga el pago del cliente verificado en su totalidad; sin pago verificado no se emite factura (RN-53).
- [ ] Se valida que la orden no tenga ya una factura electrónica emitida; si la tiene, se retorna la factura existente con código HTTP 409.
- [ ] La factura se emite a nombre del cliente titular registrado en Clientes y Solicitudes, aunque el pago lo haya realizado un tercero, y se valida que su nombre, documento y correo estén registrados (RN-57).
- [ ] La factura se transmite a la DIAN y solo queda emitida cuando se recibe el CUFE (RN-51).
- [ ] La factura emitida no puede eliminarse; cualquier corrección se hace con nota crédito (RN-56).

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La orden VEN-01532 tiene el pago del cliente verificado en su totalidad, no tiene factura emitida y el cliente titular CLI-00188 tiene nombre, documento y correo registrados.
- **Acción:** Ejecutar el endpoint POST /api/v1/facturacion/generar con ventaId VEN-01532.
- **Resultado esperado:**

  - Código HTTP 201 Created
  - Campo data.cufe contiene el código asignado por la DIAN y campo data.estadoDian = "aceptada"
  - Campo data.documentoCliente corresponde al cliente titular de la orden
  - Campo data.enviadaA contiene el correo del cliente titular
  - Campo message contiene el texto: "Factura electrónica generada exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de órdenes de venta no contiene una orden con el identificador VEN-99999.
- **Acción:** Ejecutar el endpoint POST /api/v1/facturacion/generar con ventaId VEN-99999.
- **Resultado esperado:**
  - Código HTTP 404 Not Found
  - No se genera ni se transmite ninguna factura
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No existe una orden de venta con el identificador indicado"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "facturaId", "numeroFactura", "cufe", "ventaId", "clienteId", "documentoCliente", "nombreCliente", "moneda", "estadoDian" y "enviadaA" (texto)
  - "valorTotal" (número decimal)
  - "fechaEmision" (fecha y hora ISO 8601)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** La orden VEN-01540 aún tiene saldo pendiente sin verificar (RN-53), o el cliente titular de la orden no tiene correo registrado para recibir la factura (RN-57).
- **Acción:** Ejecutar el endpoint POST /api/v1/facturacion/generar con cada una de esas órdenes.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se genera ni se transmite la factura
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No puede facturarse una orden sin el pago del cliente verificado" o "Los datos fiscales del cliente titular son insuficientes para facturar", según el caso

### ❌ Caso 5: 

- **Precondición:** La base de datos o la plataforma de la DIAN no está disponible.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD o de la plataforma de la DIAN.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - La orden queda sin factura emitida y puede volver a intentarse
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible generar la factura electrónica"
