## 📖 Historia de Usuario

Dado que soy asesor comercial de One Click Caribe y un cliente me contacta por primera vez por llamada, WhatsApp o de forma presencial,
Para tener un registro único del cliente desde el primer contacto, sin importar el canal por el que fue atendido,
Que el sistema me permita registrar al cliente titular con su documento, nombre, datos de contacto, nacionalidad y tipo de cliente.

## 🔁 Flujo Esperado

- El asesor comercial obtiene desde la interfaz los datos del cliente titular: documento, nombre, teléfono y/o correo, nacionalidad y tipo de cliente (proceso PRO-01).
- El sistema consume el endpoint /api/v1/clientes de `clientes.api` con el método POST.
- La capa API valida el formato del JSON y delega el caso de uso a `RegistrarClienteService`.
- El dominio `registro_cliente_pasajeros.domain` valida que el cliente sea persona natural según su tipo de cliente (RN-01) y que la nacionalidad esté informada (RN-04).
- El backend consulta la base de datos `bd_clientes_solicitudes` filtrando por documento para descartar duplicidad (proceso PRO-02, RN-05).
- Si el cliente no existe, se registran los campos:
- documento / Documento de identidad
- nombre / Nombre completo
- telefono / Teléfono de contacto
- correo / Correo electrónico
- nacionalidad / Nacionalidad (código ISO de 2 letras)
- tipoCliente / Tipo de cliente (`individual`, `pareja` o `grupo_familiar`)


## ✅ Criterios de Aceptación

### 1. 🔍 Estructura y lógica del servicio

- [ ] Se expone un endpoint POST que recibe en el cuerpo JSON los campos documento, nombre, telefono, correo, nacionalidad y tipoCliente.
- [ ] Se valida que documento, nombre, nacionalidad y tipoCliente estén informados, y que exista al menos uno entre telefono y correo (RN-04).
- [ ] Se valida que tipoCliente sea `individual`, `pareja` o `grupo_familiar`; el valor `corporativo` se rechaza porque la agencia no maneja clientes corporativos (RN-01).
- [ ] Se valida que el documento no tenga un registro previo en la tabla de clientes, sin importar el canal por el que fue atendido (RN-05).
- [ ] El registro no asigna beneficios, descuentos ni prioridad en futuras solicitudes (RN-02).

## 🧪 Requisitos de Pruebas

## 🔍 Casos de Prueba Funcional

### ✅ Caso 1: 

- **Precondición:** La tabla de clientes no contiene un registro con el documento 1098765432.
- **Acción:** Ejecutar el endpoint POST /api/v1/clientes con documento 1098765432, nombre, teléfono, correo, nacionalidad CO y tipoCliente pareja.
- **Resultado esperado:**

  - Código HTTP 201 Created
  - Campo success = true
  - Campo data.clienteId contiene el identificador asignado al nuevo cliente
  - Campo message contiene el texto: "Cliente registrado exitosamente"

### ✅ Caso 2:

- **Precondición:** La tabla de clientes ya contiene un registro con el documento 1098765432, creado cuando el cliente fue atendido por WhatsApp.
- **Acción:** Ejecutar el endpoint POST /api/v1/clientes con el mismo documento, ahora atendido de forma presencial.
- **Resultado esperado:**
  - Código HTTP 409 Conflict
  - No se crea un nuevo registro en la tabla de clientes
  - Campo success = false
  - Campo data.clienteId contiene el identificador del cliente existente
  - Campo message contiene el texto: "El cliente ya se encuentra registrado"

### ✅ Caso 3: 

- **Precondición:** Ejecución exitosa del endpoint.
- **Resultado esperado:** La respuesta JSON debe contener exactamente los campos:

  - "clienteId" (texto)
  - "documento" (texto)
  - "nombre" (texto)
  - "telefono" (texto)
  - "correo" (texto)
  - "nacionalidad" (texto, código ISO de 2 letras)
  - "tipoCliente" (texto)
  - "fechaRegistro" (fecha y hora ISO 8601)
  - "message" (texto)
  - "success" (booleano)

### ❌ Caso 4: 

- **Precondición:** El asesor envía la solicitud sin el campo nacionalidad, o con tipoCliente "corporativo".
- **Acción:** Ejecutar el endpoint POST /api/v1/clientes con cada uno de esos datos inválidos.
- **Resultado esperado:**

  - Código HTTP 400 Bad Request
  - No se crea el registro
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "La nacionalidad del cliente es obligatoria" o "Solo se registran clientes persona natural", según el caso

### ❌ Caso 5: 

- **Precondición:** La base de datos no está disponible o ocurre un error en la consulta.
- **Acción:** Ejecutar el endpoint bajo condiciones simuladas de fallo de BD.
- **Resultado esperado:**
  - Código HTTP 503 Service Unavailable
  - Campo success = false y campo data = null
  - Campo message contiene el texto: "No fue posible registrar el cliente"
